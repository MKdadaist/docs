Mintlify provides styled, syntax-highlighted code blocks powered by Shiki. You never need to add custom CSS — just use standard fenced code blocks with a language tag and Mintlify handles the rest, including a built-in copy button, dark-mode theming, and optional extras like line numbers and diff markers.

## Basic Code Block

Open a fenced code block with triple backticks and immediately follow them with a language identifier:

```python
def greet(name: str) -> str:
    return f"Hello, {name}!"

print(greet("world"))
```

```javascript
function greet(name) {
  return `Hello, ${name}!`;
}

console.log(greet("world"));
```

```bash
npm install @mintlify/cli --save-dev
mintlify dev
```

## Adding a File Name (Title)

Place a filename string after the language tag to display it as a title tab above the code block:

````mdx
```python app.py
from flask import Flask

app = Flask(__name__)

@app.route("/")
def index():
    return "Hello, world!"
```
````

This renders as:

```python app.py
from flask import Flask

app = Flask(__name__)

@app.route("/")
def index():
    return "Hello, world!"
```

## Line Numbers

Add the `lines` meta option to display line numbers on the left-hand side:

````mdx
```python lines
def fibonacci(n):
    if n <= 1:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)

print(fibonacci(10))
```
````

## Highlighting Lines

Use the `highlight` meta option with a comma-separated list of line numbers or ranges to visually emphasise specific lines:

````mdx
```python highlight={1,3-5}
import os

BASE_DIR = os.path.dirname(__file__)
DATA_DIR = os.path.join(BASE_DIR, "data")
LOG_DIR  = os.path.join(BASE_DIR, "logs")

print(BASE_DIR)
```
````

## Diff Markers

Annotate individual lines as additions or removals using inline comments — Mintlify renders them with green and red backgrounds:

```python
def connect(host, port):
    timeout = 30  # [!code --]
    timeout = 60  # [!code ++]
    return socket.create_connection((host, port), timeout)
```

The `# [!code --]` and `# [!code ++]` markers work for any language that supports `#` comments. For languages using `//`, use `// [!code --]` and `// [!code ++]` instead:

```javascript
function fetchUser(id) {
  const timeout = 3000; // [!code --]
  const timeout = 5000; // [!code ++]
  return api.get(`/users/${id}`, { timeout });
}
```

## Multi-Language Tabs with `<CodeGroup>`

Wrap multiple code blocks inside `<CodeGroup>` to display them as selectable tabs. This is ideal for showing the same operation across multiple languages or package managers.

Place `<CodeGroup>` as a top-level component and put each language variant as a separate fenced block inside it. Each block gets a tab label from the text after the language name (e.g., `python Python` → tab labeled "Python"):

<CodeGroup>
```python Python
import requests

response = requests.get("https://api.example.com/users")
print(response.json())
```

```javascript JavaScript
const response = await fetch("https://api.example.com/users");
const data = await response.json();
console.log(data);
```

```bash cURL
curl -X GET https://api.example.com/users \
  -H "Accept: application/json"
```
</CodeGroup>

The tab label is taken from the text that follows the language identifier — you can use any label you like, not just the language name.

## Collapsing Long Code Blocks

Add the `expandable` meta option to collapse long code blocks behind a "Show more" toggle. This keeps your page readable when you need to include lengthy configuration files or full output examples:

````mdx
```yaml expandable
version: "3.9"
services:
  web:
    build: .
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=postgres://user:pass@db:5432/mydb
      - SECRET_KEY=supersecretkey
      - DEBUG=false
  db:
    image: postgres:15
    volumes:
      - postgres_data:/var/lib/postgresql/data
    environment:
      - POSTGRES_USER=user
      - POSTGRES_PASSWORD=pass
      - POSTGRES_DB=mydb
volumes:
  postgres_data:
```
````

<Tip>
  Always include a language tag for syntax highlighting. Use `text` or `plaintext` for terminal output or unformatted content where you don't want highlighting applied.
</Tip>
